# Gait120 → MyoLeg — contact-event reset after the 969-stride audit

**Purpose:** Replace accumulated event patches with one reproducible pass over the **original GRF arrays retained inside the converted `.npz` references**, without repeating or modifying kinematic retargeting.

**Reference:** Boo, J., Seo, D., Kim, M., and Koo, S., *Comprehensive human locomotion and electromyography dataset: Gait120*, *Scientific Data* **12**, 1023 (2025), [DOI: 10.1038/s41597-025-05391-0](https://doi.org/10.1038/s41597-025-05391-0), *Methods → Data processing*.

## 1. What the paper actually says

For **level walking**, the authors identified **right-foot** gait events from vertical force-plate GRF:

- Right **heel strike (HS)**: vertical GRF **first exceeds 20 N** (rising crossing).
- Right **toe-off (TO)**: vertical GRF **drops below 20 N** (falling crossing).
- Cycles distributed in the dataset start at a **right HS** and end at the **next right HS**.

The article **does not prescribe** left-side contact annotation, fixed 50% left HS, fixed 10%/60.5% TO positions, or any imputation when force data lack a crossing. It also does not document a 20 ms refractory period. Here we use its 20 N crossing definition, and document every additional local processing choice below.

**Important:** A published right-HS-to-right-HS interval is valid as a reference stride even if its precise boundary crossings cannot be independently verified within the **cropped** force `.mot` file.

## 2. Small adjustments we previously decided to keep

| Item | Action | Origin / reason |
|---|---|---|
| 20 N threshold | Detect **upward** crossings as HS, **downward** as TO; interpolate crossing time between force samples | **Paper** |
| 20 ms refractory **per force plate** | After one accepted event, reject any crossing within 20 ms. Maintain a coherent accepted contact state, so rejected spurious re-crossings cannot create a second TO | **Our addition, requested after audit**; eliminates millisecond TO–HS–TO chatter |
| S029 Trial05 step01 | Reject the known false **plate 1 HS** around 10.18% of the stride; leave its original force trace unchanged | **Our visual QC**; transient upward crossing at toe-off |
| S115 Trial03 step02 | Reject the known false **plate 1 HS** around 11.79% | **Our visual QC**; same phenomenon |
| Force-plate side labels | When possible, assign foot using OpenSim lab-frame CoP proximity to heel/toe marker segment; ambiguous events stay **unassigned** | **Our extrapolation**, necessary to distinguish left from right across two plates, *not specified as an algorithm in the paper* |
| Missing event | Store `NaN` and source `not_observed`, **do not invent any TO/HS time** | Correct interpretation of incomplete force-plate coverage |
| Right stride phase | Preserve published segmentation: `(time - t0)/(t1 - t0)` and the original stride duration | **Paper's segmentation** and our earlier decision to preserve real time |
| S060 root quaternion sign unwrapping | Preserve prior fix (quaternion `q` and `-q` encode the same orientation) | Earlier **kinematic** QC; **not touched here** |
| S011 subtalar observation | Retain S011 without subject-specific joint sign manipulation; existing QC flag remains | Earlier **kinematic** QC; **not touched here** |
| Heading alignment | Preserve existing +Y walking direction for all 969 trajectories | Earlier **training** decision; **not touched here** |

**Removed from the event ground truth:** the estimated left HS at 50% of the stride, left TO near 10%, and right TO near 60.5%; the previous cohort-median TO selection, phase-based event acceptance windows, and forced five-event-per-stride annotation. These may be useful as separate modeling priors in the future, but are **not measurements** and are not generated by this script.

## 3. Run from the post-audit kinematic dataset

The script reads the untouched `grf_values` and `grf_time_s` already embedded in **every** reference `.npz`. Therefore, the previously applied `gait120_event_qc.py`, `fix_two_gait120_steps.py`, `apply_gait120_event_refractory.py`, and `finalize_gait120_contact_events.py` do **not** need to be rerun. They are superseded **for event annotations only**. No rerun of joint-angle extraction or heading alignment is required.

To test the first few strides:

```powershell
python rebuild_gait120_paper_events.py `
  --input-root gait120_references_forward `
  --output-root gait120_paper_events_test `
  --limit 10
```

For the full dataset (choose a NEW, EMPTY output folder):

```powershell
python rebuild_gait120_paper_events.py `
  --input-root gait120_references_forward `
  --output-root gait120_references_paper_events
```

The script never overwrites the input. It also works if the input contains earlier event CSV edits, because it **ignores the old event CSVs** and detects directly from the saved force signals.

## 4. Output format

Each `S###/Trial##/step##` contains:

- `step##.npz`: **unchanged `qpos`, `qvel`, original timestamps, original `grf_values`, marker coordinates**. The right phase is based on original stride timing. Event scalars `left_hs_s`, `left_to_s`, `right_to_s` are **observed times only**; missing/ambiguous are `NaN`. `phase_left_01` and `phase_left_rad` are calculated only if there is one unambiguous observed left HS; otherwise they are all `NaN` (no half-cycle assumption).
- `step##_events.csv`: observed, accepted 20 N crossings after the documented small QC adjustments. `foot_side=unassigned` means that the plate crossing exists, but we cannot attribute it to a particular foot. Each row is still a *force-event candidate*, not biomechanical proof.
- `step##_manifest.json`: records dataset right-HS boundaries, measured event lists, missing-event provenance, and which method was applied.

At the output root:

- `paper_event_summary.csv`: one record per stride; successful/failed processing, labeled HS/TO counts, missing events, rejected crossings, and unresolved multiple crossings.
- `paper_event_raw_crossings.csv`: every original 20 N crossing with whether it was accepted or rejected and why. **This is the place to audit our refractory/manual exclusions**.

There is deliberately **no** `step##_selected_events.csv` with imputed contact times. Old selected-event files are not copied.

## 6. Verification and scientific limitations

- Expect **969 processed** if the same complete set of `.npz` inputs is supplied; check the actual final console report and `paper_event_summary.csv` for failures.
- Inspect the `right_TO_observed` total. Some references will still lack a measured right TO because **two finite force plates do not provide continuous bilateral foot-ground contact measurement**.
- Every labeled event should correspond to an upward/downward **20 N crossing in the untouched original GRF**. The script does not use foot height to invent crossing timestamps.
- At the right-stride start and end, **the dataset's segmentation** provides the right-HS reference boundary even if no visible threshold crossing occurs at exactly the first/last force sample.
- All force and marker data remain in their **original OpenSim laboratory coordinates** inside heading-aligned references; CoP-marker association uses those original coordinates together, so no accidental mixing with the rotated MuJoCo world frame occurs.
- The paper only explicitly defines right-foot contact events. Left-side labels are an **additional inference** from CoP-marker geometry and may be unavailable even when a force crossing exists.
- Where more than one crossing remains for the same side/event despite refractory filtering, the script **flags** the ambiguity rather than choosing a convenient crossing using a gait-phase prior.

**In short:** this is a faithful 20 N GRF event re-extraction with only the explicitly documented minor QC choices. The MyoLeg kinematic references and heading alignment are left intact.
